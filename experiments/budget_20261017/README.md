# 五题预算收尾对照：结果与解释

本轮已在台式机 `PC-20230218RALO`（`192.168.1.11`）完成两组模型生成、原始官方评分和统一修正末尾换行后的完整复验。共生成 10 条轨迹，没有空补丁。模型生成估算成本合计 **0.04391898 美元**，未与供应商账单核对；评分与换行修正没有新增模型调用。

## 实验控制

两组使用此前获授权的相同五题、DeepSeek、50 次调用、每题 1 美元和 300 秒停止阈值、单 worker、关闭记忆，并启用相同检索工具与首步检索要求。每组全局费用停止阈值为 5 美元。唯一变量为收尾阈值：

| 参数 | baseline：关闭收尾 | finalization：开启收尾 |
| --- | ---: | ---: |
| finalization_step_reserve | 0 | 5 |
| finalization_time_reserve | 0 | 45 |
| finalization_cost_reserve | 0 | 0.1 |

两组冻结清单中的源码、题目、模型、工具、环境、依赖和硬预算一致。生成源码指纹为 `ce5572158751addef0a741268844ebf841bcb154f62774f16289a3b8dd81939d`；各组的 `source.zip` 保留了当时源码，包括后来发现的导出缺陷。前两轮实验保留原样，不混算。

主要指标预设为固定五题官方解决情况；辅助记录空补丁、调用数、费用、耗时与提示触发。两组各生成一次，按 baseline、finalization 顺序执行，没有根据成绩重跑模型。

## 提示实际做了什么

只有开启组的 Matplotlib 题触发提示：已使用 45 次调用、剩余 5 次调用时插入一次。第 46 次动作是 `git diff HEAD`，第 47 次动作提交补丁。补丁修改在提示前已经存在，因此可以确认收尾提示与提交路径被执行，不能说提示生成了正确修复。

关闭组同题用满 50 次后恢复了 5,392 字符的候选补丁，修改 `_base.py` 和 `_subplots.py`；开启组主动提交 820 字符补丁，只修改 `axis.py`。关闭组仍失败于 `test_shared_axes_clear[png]`，并引入 `test_sharing_does_not_link_positions` 回归；开启组官方测试通过。

邮件题没有触发收尾提示。关闭组在修正换行后通过目标测试，但 18 个原有邮件测试仍因 SMTP ASCII 编码错误失败；开启组还将 `CachedDnsName.get_fqdn()` 的结果转为 IDNA，官方测试全部通过。这项差异不能归因于收尾提示。

## 可以得出的结论

收尾触发、硬限额、主动提交与恢复补丁区分，以及导出字节验收都有实际证据。本轮开启组五题全部通过，但只有一题触发提示，且修复先于提示形成；两组空补丁均为 0。不能据此宣称收尾提高总体修复率或减少空补丁。

开启组总调用数和生成耗时均高于关闭组，也没有证据说明整体更省调用或更快。估算费用较低可能受到顺序运行时的供应商缓存影响。这是已知五题、各一次的开发验证，不是未见任务的泛化结果。

下一步若评估提示的实际作用，应在相同第 45 步对话与工作区上分叉，比较最后五次调用的提交与验收表现，再扩展到未参与调参的任务；新增模型调用需要独立实验范围和预算。
