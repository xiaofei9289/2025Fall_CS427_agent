# Sham-search control — 2026-10-19

Status: **5-task control only; no evidence that useful retrieval changes outcomes.**

## Design

C-real and C-sham use the same source, prompt, gate, tool name, schema and
description. `MSWEA_MEMORY_SHAM=1` makes `memory_search` return
`No matching messages in this run's transcript.` with `retrieval_tokens=0`.
The gate still counts the call, so both arms carry the same tool-use burden.

- Source: `caedfd8` (sham flag added; real behavior unchanged)
- Tasks: `tasks_sham5.json`
- Tags: `c_pilot_sham_real`, `c_pilot_sham_ctl`
- 5 tasks, 2 workers, generation + official grading

## Results

| Arm | Resolved | Cost | API calls | memory_search calls |
| --- | ---: | ---: | ---: | ---: |
| C-real | 4/5 | $0.1802 | 185 | 5 |
| C-sham | 4/5 | $0.3599 | 294 | 8 |

Both solved the same set: 11333, 14855, 15315, 8721; both failed 11532.
There were no real-only or sham-only resolutions.

The sham arm was more expensive and searched more often: without useful content,
the model retried `memory_search`/reads instead of recovering evidence. This is
the expected cost of a no-op tool, not evidence for retrieval.

## Interpretation

- On this 5-task subset, **useful retrieval had no measurable effect**.
- The tasks may not require transcript retrieval, and n=5 has no statistical
  power. This control cannot prove retrieval is useless in general.
- It does show that the current C treatment is not producing a visible benefit
  on the selected tasks. Do not run the formal 50-task memory comparison on this
  basis.
- If memory is pursued further, use a pre-registered 10-task × 2–3 round
  C-real/C-sham comparison on tasks selected because they actually evict
  evidence, and report paired differences with intervals.
