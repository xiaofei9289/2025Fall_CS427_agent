## The important finding

**C never called `memory_search` in any of the 10 tasks.** Search tool calls = 0, retrieval calls = 0.

The observed C−B difference is +1 task (C passes `sympy-13615`, B fails it), p=1.0, 95% CI [0.000, 0.300]. Under the pre-registered rule, this **cannot** be attributed to history retrieval. It is a prompt/tool-description effect or run noise. The C report now prints an attribution warning when `search_calls == 0`.

What the pilot did show:

- The 8000-token budget is enforceable in practice: no violations, no missing task, no clipped observation.
- B's summary is used heavily (153 calls) and is materially cheaper than A on the long `matplotlib-20826` task: A ran 386 calls and failed; B ran 82 calls and passed; C ran 65 calls and passed. Cost follows the same pattern ($0.269 vs $0.117 vs $0.079).
- B−A is net zero (1 gained: `20826`; 1 lost: `sympy-13615`), p=1.0. One run, ten tasks; not evidence of a summary effect.
- `django-11532` fails in all three arms; that is a task-level difficulty, not a memory difference.

## Cause and change

The C system prompt did contain the tool description, but the description only said what the tool does, not **when** to use it. The model never chose it.

Change for the next pilot: the C tool description now says explicitly:

> Call this whenever a file path, error, or earlier decision you need is no longer in view; do not guess or redo work.

This stays inside the C treatment (the tool and its affordance); B's prompt and the B/C summary text remain identical. It slightly increases C's pinned tokens; that cost is reported.

## Post-pilot implementation status (2026-10-18)

The pilot above is unchanged and remains feasibility-only.  After it, the clean
implementation was hardened without changing the pre-registered design:

- summarized reads are invalidated by writes in the retained window, by mixed
  read/write bash commands, and by later test failures;
- re-reads keep their latest source step and are no longer dropped by insertion
  order;
- passing tests have a separate verification section instead of being generic
  actions;
- `comparison.md` now reports estimated/actual prompt tokens, repeat reads,
  recovery re-reads, and lost read exposures.

See [implementation notes](IMPLEMENTATION_20261018.md).  The next 10-task pilot
must be run on the desktop Linux container; this Mac workspace has no Docker
task environment or model credentials.  C must make at least one
`memory_search` call before C-B is interpreted as a retrieval effect.
